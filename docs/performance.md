# 性能

面向**班级安卓平板**（Chrome 80 / Android 9 / 微信 X5）的性能基线、
测量方法与门槛。所有数字都来自实测，不是估的。

## 为什么单独有这份文档

「丝滑」是体感，但体感会骗人 —— 同一个改动，在开发机（快 10 倍）
上看不出问题，在学生的平板上就是「卡」。所以性能必须：

1. **可测**：每项都有明确指标与测量方法，不靠「感觉快了」
2. **可比**：数字都按同一个环境基准测过（CPU 4x降速 ≈ 中端平板）
3. **可拦**：`perf-gate` 能在回归时让 CI 失败，而不是靠人记得手测

## 怎么跑

```bash
cd server

# 性能门槛（CI 用；需要跑着一个实例）
npm run perf:gate -- http://127.0.0.1:9046

# 功能验证（需要先 source .env）
npm run verify:all
```

### perf-gate 的前置条件

- 一个跑着的 Cluss 实例，且 `client/dist` 已构建
- 一个能登录的测试账号：`SETUP_ACCOUNT` / `SETUP_PASSWORD`（默认 `uitester` / `Test1234`）
- 笔记项会**自动注入** 60 条测试数据（实测过：注入失败会记为不通过，
  因为空列表会让门槛形同虚设）
- 流式项需要一个已配好模型的实例；没有就设 `PERF_SKIP_STREAM=1` 跳过

### 环境差异

CI 机器比本地慢是正常的。两个办法：

```bash
CPU_THROTTLE=2 npm run perf:gate -- http://...   # 调降速比例
```

**不要为了让 CI 变绿而放宽 `perf-baseline.json`。**
确实是环境差异就调 `CPU_THROTTLE`；确认是代码退化就修代码。

全部走系统 Chrome 的 CDP（`CHROME_PATH` 可覆盖）。

## 已做的优化及其原理

### 切页动画：从「布局动画」改成「合成器动画」

离场页原来用 `position: absolute`，这让整页在动画期间脱离文档流，
浏览器**每帧都要重新布局** —— 页面里有多少元素就重排多少
（Notes.vue 有 7000+ 行 DOM）。而 `transform` / `opacity` 本来是
合成器能独立处理、不触发重排的属性，被 absolute 一搅就退化成
「重排 + 重绘 + 合成」三件套。

改为两页都留在文档流、离场页用负 margin 拉出视口：margin 变化只触发
**一次**重排（进出场开始时），动画全程只有 transform 在动。

实测：最长阻塞 360 → 122 ms。

### 页面预取

所有页面都是异步组件（`router` 里一律 `import()`），首次点某标签要现场
下载 chunk（Notes 243KB / Chat 41KB）—— 平板移动网络下就是几秒空白。

`nav-items.js` 给每个导航项挂上 chunk 加载函数，`App.vue` 在
`requestIdleCallback` 里预取。用空闲回调而不是 `mounted` 里直接 import：
首屏还在渲染、正在跑 mermaid/katex 初始化，抢主线程会把首屏也拖慢。

### 笔记列表虚拟滚动

实测 60 篇笔记时切入该页**每次**都付 75~87ms（不是只付一次）——
全量渲染产生 1621 个 DOM 节点与 726 个事件监听器，每次进出都要创建再销毁。

`components/VirtualList.vue` 只渲染可视区附近的条目。

变高条目的处理：常见虚拟滚动假设「所有条目等高」，但笔记列表不是
（带标签 93px / 不带 69px），等高假设会让滚动位置越滚越偏。
这里用实测均值估算 + 渲染后修正 + 滚动中持续自适应。

代价：**Ctrl+F 搜不到未渲染的文本**。项目基线是触屏优先，这个取舍可接受；
若要保留浏览器原生查找，需改用「定高 + 统一视觉高度」的方案。

## 两个自己踩的坑（改代码前先看一眼）

**自激循环**：测量函数写 `measuredAvg` → 改变 `startIndex/endIndex` →
`visibleItems` 变化 → 触发 watch → 再测量。切页耗时从 90ms 抬到 120ms，
表现为「DOM 变少了反而更慢」，极具迷惑性。

**自己的代码成了瓶颈**：虚拟滚动做完第一次测量反而更慢，CPU 采样显示
87.6% 是 idle、JS 只占 10%，而 top 里是 `syncViewport` 和 `scrollToIndex`
—— Vue 2 的 data 写入会触发依赖重算，无条件赋值等于强行让整棵列表重算。
全部改成「值真的变了才写」。

**教训**：性能问题不能靠读代码判断，一定要测。上面两个如果没实测，
一个会继续「优化」错的地方，一个会留在代码里长期拖慢每一页。
