# 部署与运维

> 本文是 [README](../README.md) 的分册：生产运行要点、接入 AI 上游、版本号与发布、充值流程。
> 部署步骤本身（含一键启动与多班部署）见 [README 快速开始](../README.md#快速开始)。

## 生产运行要点（生产环境必须逐条过一遍）

```ini
NODE_ENV=production              # 切紧凑日志格式
PORT=9003
JWT_SECRET=<32位以上随机串>       # 缺失直接拒绝启动，绝不用默认密钥
```

- **先构建再启动**：服务端托管 `client/dist`，没有构建产物时只提供 API（启动日志会提醒）。
  也可以用根目录 `npm start` / `start.bat`，脚本会自动判断补齐装依赖与构建
- **升级流程**：停服 → 备份 `database/`（`cluss.db`/`-wal`/`-shm` 三件套）→
  `git pull` → 两个 `package.json` 各自 `npm install`（如有依赖变化）→
  `cd client && npm run build` → 起服 → `curl /api/health` 核对版本号
  （装依赖与构建两步可交给根目录 `npm start` 自动判断补齐）
- **探活**：`GET /api/health` 无需鉴权，返回版本/模式/实例标识/同步状态，可直接接监控
- **进程守护**：建议用 systemd / pm2 托管（服务端已支持 SIGTERM 优雅退出）
- **备份与清理**：
  `node scripts/backup.js`（在线备份，单文件完整库，默认保留 7 份，`--keep` 可调）
  与 `node scripts/cleanup-orphans.js`（云盘孤儿文件清理，默认 dry-run，`--delete` 执行）。
  前者建议放进 cron / 计划任务每日一跑，后者磁盘增长明显时再跑

### 备份 SQLite 的正确姿势（踩过坑）

库开了 WAL，**大部分最新数据在 `cluss.db-wal` 里**，不在 `cluss.db`。
只复制 `cluss.db` 再还原，会静默回滚到上一次检查点 —— 数据看起来"没丢"，其实丢了一批。

两条路任选：

1. 三个文件一起拷：`cluss.db` / `cluss.db-wal` / `cluss.db-shm`
2. 先把 WAL 折进主库再单文件拷贝：

```bash
node -e "require('dotenv').config();require('./src/utils/db').pragma('wal_checkpoint(TRUNCATE)')"
```

## 接入 AI 上游

Cluss 只要求上游是 **OpenAI 兼容**（`/v1/chat/completions` + SSE 流式），
在管理台填地址、Key、模型名即可。接入后建议用管理台「模型与单价」里的
**连通性测试**确认可用，再放给学生。

### 推荐做法：用原生支持图片的 API 服务

「网页反代」（把 DeepSeek 官网包成 OpenAI 接口）有一条绕不过去的硬伤：
**它们不支持图片输入** —— 实测两个主流反代项目，`ref_file_ids` 都是硬编码的空数组、
也没有文件上传端点。而拍题与批改完全依赖视觉，所以那类上游只能靠「转述模型」兜底。

换成**原生支持图片的 API 服务**就没有这个问题：

```bash
cd server
node scripts/connect-freeshare.js --key=sk-xxx
```

同样**先实测视觉再写库**（带随机四位的图，答对才算），然后注册模型：

| 模型 ID | 学生看到 | 上游模型名 | 视觉 |
|---------|---------|-----------|------|
| `ds-v41` | 标准 | `deepseek-v4.1-flash` | **原生支持** |
| `glm53f` | 快速 | `glm-5.3-flash` | 无（靠转述兜底） |

**标签按实测写，不按名字猜。** 试配时曾想给 `glm-5.2` 标「深度思考」——
它确实输出 `reasoning_content`；但换成 `glm-5.3-flash` 后实测
**没有**推理输出（同一题 65 tokens、无思考内容），所以标「快速」。
标签是学生看的，**名不副实比没有选项更糟**。

顺带一个反直觉的实测结论：**会说"不支持"的模型比"沉默"的模型安全**。
`glm-5.3-flash` 遇到图片直接回 **HTTP 400 + 明确原因**；
而 `glm-5.2` 回 200 却在正文里说「我看不到图片」——后者会让模型对着没看到的题硬答。

> 前端模型下拉在 `models.length > 1` 时才渲染（只有一个可选时它没有意义）。
> 所以如果只配了一个可用模型，看不到选择框是**预期行为**，不是 bug。

实测通过（2026-10-03）：

- **原生视觉** —— 拍题与批改走原始链路，不再需要转述模型
- **流式末尾回 usage**（含缓存明细）→ `estimated: false`，计费精确，学生端不弹「估算用量」
- **不绑定个人网页会话** —— 没有「token 几小时过期、要手动换」那类运维负担

> 端到端怎么验（不要只看接口 200）：生成一张写着**随机算式**的图，
> 走「上传 → 拍题」全链路，断言模型读出算式**并且算对**。
> 只断言 200 是不够的 —— 图片被静默丢弃时接口同样返回 200，
> 模型会对着没看到的题一本正经地硬答。

### 视觉能力：不要信文档，要实测

很多 OpenAI 兼容上游对"是否支持看图"语焉不详，甚至有上游**接受** `image_url`
内容块、也回 200，但内部把图片悄悄丢掉。项目自带实测工具 `scripts/probe-vision.js`：

```bash
node scripts/probe-vision.js --model ds-web               # 测库里已配置的模型
node scripts/probe-vision.js http://host:8080 sk-key model
```

**做法**：生成一张带**随机四位数**的图片发过去，问它数字是多少。

| 回复 | 结论 | 退出码 |
|------|------|--------|
| 说出了那个数字 | 真能看图（模型不可能猜中，所以"答对"是有意义的证据） | 0 |
| 「看不到图片」 | 不支持（图片被上游丢弃） | 1 |
| 其它 | 存疑 —— 原图会落盘到临时目录，请人工核对 | 1 |

随机数是关键：模型不可能猜中，所以"答对"是有意义的证据。

**为什么必须实测**：上游"看起来支持"而实际丢弃图片时不会报错，
模型会对着一个它根本没看到的题一本正经地作答——学生拿到的是
看起来正常的错误答案，**这比直接报错危险得多**。

若上游确实不支持视觉，**拍题与批改需要另配一个能看图的「转述模型」**
（管理台「视觉配置」）：让它先把图片转成文字，再喂给纯文本模型。
没配时学生会看到「看图功能暂时不可用，请联系管理员」——
这是刻意的人话提示，而不是让请求打到一半才报一个看不懂的错。
原理见 [product.md 的「看图是怎么工作的」](product.md)。

### usage 从哪来（以及为什么曾经过不准）

Cluss 优先用上游返回的 `usage`；拿不到才回退到本地估算，并在 `done` 事件里标记 `estimated`。

**两个反代项目已做"取长补短"合并**，把 deepseek2api 的强项移植进了 web2api：

1. **计数器换成 DeepSeek 自己的 tokenizer**（`tokenizer.json` + `tokenizers`）。
   原来用 tiktoken 的 `cl100k_base`——那是 OpenAI 的分词器，实测对中文
   **高估 120–131%**（88 字中文报 113 token，真实 49）。中文为主的场景下这会直接扭曲计费。
   现在 `token_counter.py` 是三级后端：真 DeepSeek tokenizer → tiktoken → 字符启发式，
   `GET /health` 会报告当前生效的是哪一个（静默回退会表现为莫名的计费漂移，所以做成健康信号）。
2. **流式末尾补发 usage chunk**（符合 OpenAI 规范：`choices: []`，
   仅在调用方带 `stream_options.include_usage` 时发）。
   顺带修掉一个隐藏入口：`ChatCompletionRequest` 里原本**没有 `stream_options` 字段**，
   pydantic 静默丢弃——调用方要了也拿不到，这才是"只能本地估算"的根因。
   注意它的 `event_stream` 有 **4 条不同的结束路径**，usage 必须收口到统一出口，
   否则会出现"模型调不调工具决定计费准不准"。

> 反直觉但重要：**只补 usage 不换 tokenizer 会让计费更糟** ——
> 那等于开始按 2.3 倍的中文计数收费。这两件事必须一起做。

Cluss 侧无需任何改动就能受益（它读任意 chunk 的 `usage`，且对 `choices: []` 有守卫），
所以现在 `estimated` 会变成 `false`，学生端不再弹「本次用量为估算值」。

**免费模型的「估算用量」提示仍然被抑制**——估算只影响计费，而免费模型不产生费用，
弹提示只会让学生困惑（数据库里仍如实记录）。

### ⚠️ 这个后端的会话 token 会过期（运维要点）

实测（2026-10-03）：`.env` 里的 `DEEPSEEK_TOKEN_1` / `DEEPSEEK_COOKIES_1` 是**网页会话凭据**，
有效期以小时计。过期后的表现很有迷惑性：

- 进程照常启动，`/v1/models` 也正常返回（那是静态列表）
- **只有真实对话会失败**，服务端日志里是 `40003 - Authorization Failed (invalid token)`

**它不支持用密码自动续期** —— `account_pool.relogin()` 只是"重新做一次健康检查"，
`AccountUpdateRequest` 收的是 `token`/`cookies`，代码里没有任何 password 字段。
所以要恢复，只能重新登录 deepseek.com、把新的 token 与 cookies 更新进去
（改 `.env`，或走它自带的 WebUI）。

**这对"每天给学生用"的场景是个硬伤**：需要有人定期手动续。要长期稳定，
要么接受这个维护成本，要么换成有正式 API Key 的上游。

### 模型 label 是给学生看的

`label` 会出现在学生的模型下拉里。**不要写型号名** ——
中学生分不清 `deepseek-flash` 和 `deepseek-reasoner`，
但一眼能懂「标准」和「深度思考」的区别。这属于"去术语化"的一部分。

### 定价的粒度提醒

按上游真实价格定价时，**一次对话的成本常常不足 1 积分**
（实测一次短问答约 0.1 积分，会被四舍五入成 0，学生看到"已用 0 积分"）。
累计消耗是按微元累加的，所以不会丢账，只是短期内看不出来。
如果希望学生能直观看到消耗，有两个办法：调高单价，或调大 `CLUSS_POINTS_PER_YUAN`
（后者是全局的，会同时改变所有学生已看到的积分总额，建议学期初调）。

## 版本号与发布

### 版本号制度（SemVer）

版本号 `主版本.次版本.修订号`（如 `0.1.0`），**唯一来源是两个 `package.json` 的 `version` 字段**，
发版时两处必须同步改成同一个值：

| 场景 | 改哪个位 | 例子 |
|------|---------|------|
| 不兼容的接口/数据变更（含迁移破坏） | 主版本 | `0.x → 1.0.0` |
| 向后兼容的新功能 | 次版本 | `0.1.0 → 0.2.0` |
| 纯缺陷修复 / 文案 / 样式修补 | 修订号 | `0.1.0 → 0.1.1` |

`0.x` 阶段（当前）接口尚不稳定：次版本升级允许包含小的破坏性变更，但必须在
`CHANGELOG.md` 里显著标注迁移办法。进入 `1.0.0` 后严格遵守 SemVer。

### 发版清单（release checklist）

1. 确认 `verify-v2.js` 全绿（生产配置先备份 `database/` 三件套）
2. 同步改 `client/package.json` 与 `server/package.json` 的 `version`
3. 在 `CHANGELOG.md` 顶部新增本版本小节（新增/修复/破坏性变更，面向部署者写）
4. `cd client && npm run build`，本地 `NODE_ENV=production` 起服务过一遍生产冒烟
5. 提交：`chore(release): vX.Y.Z`，并打带注释的标签：`git tag -a vX.Y.Z -m "..."`
6. `git push && git push --tags`，在 GitHub Releases 页用标签内容发 Release

### 版本从哪里能看出来

- `GET /api/health`：`data.version`（无需鉴权，监控探针专用，不含敏感信息）
- 服务端启动横幅第一行：`版本 : vX.Y.Z`
- 学生端右上角用户菜单底部：`Cluss vX.Y.Z`（前端构建时从 `client/package.json` 读入）

## 充值流程（对应你的真实收款方式）

```
学生微信/支付宝转账给你
  → 在管理台找到该生（按学号或姓名搜）
  → 填额度与周限额、写备注（如「微信转账 30 元」）
  → 确认 → 记账 → 各节点在一个同步周期内自动生效
```

流水**只增不改**，每笔都记录 `operator_id`，可随时导出对账。
