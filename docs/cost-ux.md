# 成本管理与用户体验的平衡（调研分析）

> 回答一个问题：**积分该管多紧、该露多少？**
> 结论先行：把成本控制全部放进管理员侧（离线、不打扰），学生侧只保留**确定性**——
> 预付积分、可查证、渐进预警。以当前真实定价，30 人班级月成本在 28~226 元量级，
> **体验优先不会威胁成本安全**；真正要防的是滥用与失控，而不是正常提问。

## 一、成本账（按真实配置推算）

基准价 = v4 vision ×1.00：输入 2 / 输出 8 / 缓存读 0.04（元/百万 token）；
峰谷 = DeepSeek 官方口径（高峰 09:00–12:00、14:00–18:00，其余五折）。
以下数字由 `pricing.calcCostMicro` 用真实函数算出，非拍脑袋：

| 场景 | 峰时 | 谷时 |
|------|------|------|
| 首轮（冷，3000 入 / 800 出） | 1.24 积分 | 0.62 积分 |
| 后续轮（暖，2600 缓存命中 / 400 新入） | 0.73 积分 | 0.37 积分 |
| 拍题（5500 入 / 1200 出） | 2.06 积分 | 1.03 积分 |
| ds-v41 ×1.05 后续轮 | 0.77 积分 | — |

**规模推算**（一次四轮引导会话 ≈ 3.43 积分 ≈ 3.4 分钱）：

| 强度 | 月成本（22 课日） |
|------|------------------|
| 30 人 × 每人每天 5 轮 | ≈ 28 元 |
| 30 人 × 每人每天 10 轮 | ≈ 57 元 |
| 30 人 × 每人每天 20 轮 | ≈ 113 元 |
| 30 人 × 每人每天 40 轮 | ≈ 226 元 |

三个结构性结论：

1. **缓存是最大的成本优化，且零体验代价**。多轮会话命中上游前缀缓存后，
   输入成本从 0.006 元降到 0.0001 元（1/50）。`X-Conversation-Id` 会话复用
   已内置——这条机制比任何"省着用"的规则都值钱，别动它。
2. **成本大头是输出 token（暖轮占 88%）**。引导式对话的输出天然短
   （提示词约束"不直接给答案"），这恰好是最便宜的交互形态。
   "让模型少啰嗦"永远比"让学生少提问"省得多、且体验正向。
3. **学生侧的钱其实是够的**。10 元 = 1000 积分 ≈ 291 次完整四轮会话。
   正常学习的消耗速度远低于闸门，学生几乎不会碰到硬拦截——
   所以闸门文案与预警的**质量**远比额度的**数量**重要。

## 二、体验侧：焦虑从哪来

按「可见 × 可控」给焦虑源定位：

| | 不可控 | 可控 |
|---|--------|------|
| **可见** | 每条消息标价（计价器效应，反复的微小损失刺激） | 低余量预警 + 明确下一步（适度张力，健康） |
| **不可见** | 规则悄悄变化、数字对不上账（恐慌："积分怎么少了"） | 默认隐藏消耗、随查随有（**当前设计，最低焦虑**） |

行业共识（用量计费类产品的通行做法）与我们的一一对照：

| 行业最佳实践 | Cluss 现状 |
|--------------|-----------|
| 预付积分优于跳字计费（心理模型从"正在烧钱"变"还有多少"） | ✅ 本来就是预付积分 |
| 花费上限让人不必自我审查（self-policing 杀死使用意愿） | ✅ 周限额 + 余额闸门兜底 |
| 实时用量可查是信任的基石 | ✅ 用量页两位小数、估算带「约」，每轮结算后钱包即时刷新 |
| 给"一次大概花多少"的确定性感（示例区间） | ⚠️ 缺——学生不知道"正常用是多少"（见 P2） |
| 防失控（runaway usage 的意外账单） | ⚠️ 学生侧有闸门；**管理员侧缺预算视角**（见 P1） |
| 不惩罚尝试（试错被扣费会杀死探索） | ✅ 限免机制 + 默认模型免倍率标 |

## 三、平衡点

**成本控制全部放在管理员侧与离线侧；学生侧只放确定性。**

学生侧三原则（已全部落地）：

1. **可预测**——平时没有计价器，钱包只显示余量；模型选择器的倍率徽标
   给的是"相对贵贱"而非金额，锚定在默认模型上；
2. **可查证**——用量页精确到分、可对账（本轮修复的取整失真正是为了这个：
   数字对不上账造成的恐慌，比小数点本身大一个数量级）；
3. **可行动**——预警渐进（30% 提前量）、文案给理由和出路（周限额文案解释
   "为什么有限制、额度按天回补"）。

管理员侧四杠杆（已全部落地）+ 两个缺口：

| 杠杆 | 作用 | 学生感知 |
|------|------|---------|
| 基准价（默认模型） | 跟随上游调价，一处改全站 | 无 |
| 倍率（逐模型） | 分层定价 / 摊薄贵模型成本 | 选择器上的相对徽标 |
| 峰谷五折 | 削峰填谷，摊平上游峰时成本 | 谷时一条"优惠时段"提示 |
| 限免 | 激励尝鲜、错峰 | 到期前无打扰，用完自动恢复 |
| **预算视角（缺，P1）** | 管理台显示"本月已消耗 X 元"，设阈值告警 | 无 |
| **异常检出（缺，P1）** | 单生日消耗 Top N、突增提示 | 无 |

这两项缺口是**纯管理侧工具，零学生焦虑**，是当前性价比最高的补强方向——
成本安全的短板在管理员的可见性，从来不在学生的额度上。

## 四、建议清单（按 体验代价 / 成本收益 排序）

**P0（已具备，别动）**
隐藏计价器 · 两位小数对账 · 渐进预警文案 · 会话缓存复用 · 停止生成不扣学生积分。

**P1（建议做：零学生体验代价，补管理员成本可见性）—— 已落地**
1. ✅ 管理台「学生额度」页新增「本月消耗」卡片：按服务器本地日历月聚合，
   可设预算阈值（`PUT /admin/budget`，0 = 关闭），超限卡片转红并挂「超预算」徽标；
2. ✅ 管理台「用量统计」页新增「异常检出」面板（`GET /admin/usage/anomalies`）：
   近 7 天消耗 Top 10；最近 24 小时消耗 ≥ 0.5 元且 ≥ 前 7 天日均 3 倍的账号
   标记为突增（滚动窗口，避开日期边界语义）。

**P2（可选：小体验代价，中等收益）**
1. 用量页给一句静态参考：「一次引导对话通常 1~2 积分」——行业经验表明
   "知道正常水位"能显著降低"我是不是用太快"的不确定感；
   放在用量页而非对话页，避免常驻刺激；
2. 限免到期前 24 小时在模型选择器把「限免」徽标改为「限免 · 今日截止」——
   让限免以惊喜开始、以预告结束，而不是突然恢复计费让学生措手不及。

**反模式（明确不做）**
- 每条消息旁标价（计价器焦虑，违背产品底线）；
- 按次计费（惩罚引导式多轮，成本风险反而转嫁不了）；
- 积分有效期 / 过期作废（校园场景极伤信任，且与"积分是余量不是消费"的定位冲突）；
- 低余额高频推送（一天一条的提醒=一天一次的焦虑）。

## 五、口径与假设

- 单轮 token 假设：冷轮 3000 入 / 800 出；暖轮 2600 命中缓存；拍题 5500 入 / 1200 出
  （含图像 token 估算）。真实分布以 `cluss_usage_log` 为准，可用
  `verify` 台账或管理台用量页校准；
- 22 课日/月；倍率 ×1.00；谷时按五折；上游实际扣费与 Cluss 记账同源
  （基准价即反推后的渠道价），班级月成本≈管理员上游支出（±渠道差价）；
- 行业实践参照：SaaS 定价页决策架构（dardesign.io）、用量计费的"账单惊吓"
  与信任损耗（toolrelief.com）、预付积分模型（dodopayments.com）、
  实时用量面板与信任（kinde.com）、按人设上限以停止自我审查的实践
  （LinkedIn 从业者经验）。
