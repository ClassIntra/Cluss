# Cluss

引导式 AI 解题应用。**可独立部署，也可与 ClassIntra 深度联动。**

面向学生：不直接给答案，先分层给提示、检查你的解法，让你真正想通。
面向管理员：学生线下转账后，你在后台给他开通额度，余额用完即停。

---

## 核心设计：三种运行模式

同一份代码，靠 `.env` 的 `CLUSS_MODE` 切换三种形态：

| 模式 | 用途 | 数据库 | 额度来源 |
|------|------|--------|----------|
| `standalone` | 单机独立部署（无 ClassIntra） | 自有 `cluss.db` | 本机管理员直接分配 |
| `node` | 班级节点（每班一台） | 自有 `cluss.db` | 从中继拉取，本地扣费 |
| `relay` | 中继权威节点（老师操作台） | 自有 `cluss.db` | 权威账本，管理台在此 |

### 为什么是「每班一个节点 + 一个中继权威」

现实约束：**学生只能访问本班机器**，且**充值统一由一个人管理**。这两条决定了架构：

```
                        ┌──────────────────────────────────┐
                        │   中继权威节点（relay）           │
                        │   权威额度账本 + 管理台           │
                        │   唯一充值入口                    │
                        └───────────────┬──────────────────┘
                                        │ 单向下发（出站拉取）
                  ┌─────────────────────┼─────────────────────┐
                  ▼                     ▼                     ▼
          1班 Cluss 节点         2班 Cluss 节点         3班 Cluss 节点
          本地扣费 + 本地闸门    本地扣费 + 本地闸门    本地扣费 + 本地闸门
                  │                     │                     │
                  └────── 用量汇总上报（对账用）──────────────┘
```

关键取舍：

- **扣费本地化**：学生用 AI 时不依赖网络往返，断网也能用；也避免跨实例并发扣费的分布式锁问题。
- **充值单点化**：只有中继能分配额度，天然唯一权威，不需要多写冲突消解。
- **额度是「分配」不是「共享账本」**：可用余额 = 中继下发的分配额 + 同步容错 − 本地消耗。
  余额不落库（落库必然与流水漂移），每次由流水聚合推导。
- **同步容错**：`CLUSS_SYNC_TOLERANCE_YUAN`（默认 1 元）防止「学生刚在别班充值、
  本班还没同步到」被误拒。宁可短暂放宽，也不误伤已付款的学生。

### 中继不可达时会发生什么

| 场景 | 行为 |
|------|------|
| 断网 + 学生用 AI | 正常（本地扣费不依赖网络） |
| 断网 + 管理员充值 | 管理台在中继上，此时本来也访问不到，无一致性问题 |
| 节点拉不到新额度 | 沿用上次同步的分配额 + 容错，恢复后按版本号自动对齐 |
| 节点上报失败 | 用量留在本地 `synced=0`，下个周期继续重试，不丢账 |

## 账号体系

### 学号规则：`YYNNCC`

| 段 | 含义 | 例（2025 年入学 · 3 班 · 第 7 个注册） |
|----|------|--------------------------------------|
| YY | 入学年份后两位 | `25` |
| NN | 班级号 | `03` |
| CC | 班内注册编号（01~99） | `07` |
| 结果 | | **`250307`** |

- 与 ClassIntra 的学号体系天然对应，联动部署时账号可直接照面，**不需要映射表**。
- 某班某届 99 个编号用尽时，自动回落到 `800001+` 保留段（注册成功提示会说明），
  `enrollment_year` 与 `class_no` 字段仍然记录真实学籍。
- 学号在注册时按「年份 + 班级」自动分配，学生不需要自己填。

### 与 ClassIntra 的关系

**账号分开存储，通过委托认证互通**——这条是刻意的设计决定：

Cluss 的注册是**开放的**（填姓名+年份+班级即可用），而 ClassIntra 的注册**必须通过预注册名单审核**。
如果两者共享同一张用户表，Cluss 的开放注册就等于给 ClassIntra 的白名单开了后门
（未经审核的账号能直接登录 ClassIntra，甚至可能绕过名单）。

所以：

```
独立部署：Cluss 完全自兜 —— 本地账号 + 本地额度，不依赖 ClassIntra
联动部署：Cluss 额外挂一条到 ClassIntra 的委托认证桥
          ClassIntra 的准入规则（pre_records）原样保留、原样生效
```

联动时的登录流程：

```
输入账号口令
  ├─ Cluss 本地命中  → 本地校验（独立部署时的主路径）
  ├─ 未命中且桥可用 → 调 ClassIntra /api/cluss-bridge/verify 校验
  │                    ├─ 成功 → 落库到 Cluss（source='classintra'，含口令哈希，支持此后离线登录）
  │                    └─ 失败 → 「账号或密码错误」
  └─ 未命中且桥不可用 → 「账号或密码错误」
```

ClassIntra 侧只需在 `app.js` 挂一行路由（见 `server/src/routes/cluss-bridge.js`），
**该文件是只读的**：只有 `ping` 与 `verify` 两个端点，不做任何写操作。

## 计费与额度

### 两道闸门（按顺序）

```
学生发消息
  ├─ 闸门1 余额：尚未分配额度 / 可用余额 ≤ 0 → 402「你的账号还没有开通额度…」
  ├─ 闸门2 周限额：近 7 天消耗 ≥ weekly_quota_micro → 402「本周额度已用完…」
  └─ 放行 → 流式生成 → 完成后按上游真实 usage 计费
        ├─ cluss_usage_log 落明细（余额由它聚合推导）
        └─ 剩余额度随 done 事件回传前端
```

- **免费模型**（`is_free=1`）不受两道闸门限制。
- 扣费在回答**完成之后**结算：事前扣款一旦失败就要回滚，事后结算宁可少收一次，
  也不打断正在生成的回答（末次可能略微透支，可接受）。

### 金额口径

全整数运算，单位「微元」（1 元 = 1e6 微元），与 ClassIntra 完全一致，便于对账时无需换算。

| 字段 | 单位 | 说明 |
|------|------|------|
| `price_in` / `price_out` / `price_cache_hit` | 微元 / 千 token | `1 元/百万 token = 1000` |
| `cost_micro` / `allocated_micro` | 微元 | 展示时再除以 1e6 |

**缓存命中要单独计价**：上游（如 DeepSeek）的 `prompt_tokens` 已包含命中部分，
若整段按输入价算会重复收费。命中部分按 `price_cache_hit` 算，未命中按 `price_in` 算；
未配 `price_cache_hit` 时命中部分回落按 `price_in`（不欠费也不错收）。

## 快速开始

### 独立部署（单机）

```bash
cd server
cp .env.example .env
# 编辑 .env：至少填 JWT_SECRET 与 ADMIN_PASSWORD
npm install
npm start            # 默认 http://localhost:9101
```

```bash
cd client
npm install
npm run build        # 产物输出到 client/dist，由服务端直接托管
```

首次启动会：

1. 自动建表（迁移 v1、v2）
2. 写入 `.env` 里配置的默认 AI 模型
3. 用 `ADMIN_USER_ID` / `ADMIN_PASSWORD` 创建管理员账号（**已存在则不覆盖密码**）

> 别忘了在管理台给模型填上 API Key，否则学生发消息会收到「AI 服务未配置完成」。

### 多班部署（1 个中继 + N 个节点）

**中继节点**（老师操作的机器）：

```ini
CLUSS_MODE=relay
PORT=9101
CLUSS_INSTANCE_ID=relay
JWT_SECRET=<32位以上随机串>
CLUSS_SHARED_SECRET=<与各节点一致>
ADMIN_PASSWORD=<管理台密码>
```

**班级节点**（每班一台）：

```ini
CLUSS_MODE=node
PORT=9101
CLUSS_INSTANCE_ID=class-01          # 每班必须唯一，用于对账区分
JWT_SECRET=<与中继一致>
CLUSS_RELAY_URL=http://<中继地址>:9101
CLUSS_SHARED_SECRET=<与中继一致>
```

节点会自动：启动立即同步一次 → 之后每 `CLUSS_SYNC_INTERVAL` 秒拉额度 →
每 `CLUSS_REPORT_INTERVAL` 秒上报用量。管理台在**中继**上，节点上不需要登录管理台。

### 与 ClassIntra 联动（可选）

**ClassIntra 侧**：`.env` 里确保配置了 `RELAY_SECRET`，然后重启：
`/api/cluss-bridge/ping` 与 `/verify` 即生效（未配密钥时返回 503，不影响现有功能）。

**Cluss 侧**：

```ini
CI_BRIDGE_URL=http://<ClassIntra 地址>:9001
CI_BRIDGE_SECRET=<与 ClassIntra 的 RELAY_SECRET 一致>
CI_JWT_SECRET=<与 ClassIntra 的 JWT_SECRET 一致>   # 填了才支持 token 互认免登
```

## 功能地图

**学生端（六个入口）**

| 入口 | 能做什么 |
|------|---------|
| 对话 | 学习模式（引导式 / 直接给答案）与日常模式；可附云盘里的图片与文本文件 |
| 学习 | 拍题解答（单题 / 多题 / 跨页题）与作业批改；支持**现拍**（直接调系统相机） |
| 作文 | 生成范文 / 批改润色 / 列提纲；可选语言、文体、风格、字数；支持看图作文与手写稿批改 |
| 记录 | 解题与批改的历史记录（类型徽章 + 题图缩略图 + 摘要），点击回看完整结果 |
| 错题本 | 批改出的错题**自动收录**，可筛选、编辑、标记已掌握、批量操作、导出 CSV |
| 云盘 | 上传图片与文本、预览、下载、删除；每用户默认 200MB 配额 |

「我的消耗」在右上角用户菜单里（低频页，不占顶栏）。

**管理端（四个标签页，`/#/admin`）**

| 标签页 | 能做什么 |
|--------|---------|
| 学生额度 | 总览指标、学生列表（搜索 / 按班级筛选）、单人充值、**批量充值**、充值流水、台账导出 |
| 模型与单价 | 增删改任意 OpenAI 兼容模型、设默认、启用/禁用、单价与免费标记、连通性测试 |
| 视觉配置 | 看图总开关、转述模型选择、单次图片数上限、压缩参数 |
| 用量统计 | 全站用量（按学生/模型/类型/天/实例分组）、调用明细、CSV 导出 |

**充值流程**（对应你的真实收款方式）：

```
学生微信/支付宝转账给你
  → 在管理台找到该生（按学号或姓名搜）
  → 填额度与周限额、写备注（如「微信转账 30 元」）
  → 确认 → 记账 → 各节点在一个同步周期内自动生效
```

流水**只增不改**，每笔都记录 `operator_id`，可随时导出对账。

### 看图（拍题与批改）是怎么工作的

模型侧分两条路：

```
模型自身支持视觉  → native：直接把图片作为 image_url 内容块传给它
模型不支持视觉    → relay ：先用「转述模型」把图片转成文字，再把文字喂给它
两者都不行        → 拒绝请求，并给出可操作的中文提示
```

`relay` 存在的理由：教室里常用的便宜模型多是纯文本的，收图会直接 400。
配一个视觉模型专门做「看图转文字」，就能让这些便宜模型也具备拍题能力。

几个实现上的取舍：

- **转述串行、不并发**：同一个 API Key 并发调转述大概率撞上游限流（429）。
- **转述消耗单独记账**（`source='vision_relay'`），并与主回答共享同一个 `trace_id`，
  这样对账时能算出「这次拍题总共花了多少」。
- **闸门按「实际出钱的模型」判**：免费主模型 + 收费转述模型时，两个都要过闸门，
  否则会被白嫖。
- **图片只存引用不存内容**：`ai_messages.attachments` 里只有 `hash` 与文件名，
  base64 只存在于内存与请求体中。否则会话表会被几 MB 的字符串撑爆。
- **历史消息不回填图片**：只留 `[图片：xxx]` 文字占位，每张图按 1200 token 计入预算。
  否则 20 条历史里混 10 张图，光历史就要吃掉 12000 token。
- **服务端缩图**：手机题图常在 3~8MB，用 sharp 压到长边 1568 以内再传上游。
  sharp 装不上或压缩失败时**回退原图**，绝不因压缩问题让对话不可用。

### 错题是怎么自动进本子的

不能让前端去正则解析批改表格——模型表格格式一变就抓不到，而且流式过程中表格是半截的。

做法是让模型在批改表格之外**额外输出一段带标记的结构化数据**：

```
<wrong-items>
[{"subject":"物理","question":"…","student_answer":"…","correct_answer":"…","reason":"…","tag":"✗"}]
</wrong-items>
```

配套三处处理：

- **后端提取**：解析这段 JSON 写入 `wrong_questions`（带来源会话与题图 hash）。
  解析失败只记日志——错题本拿不到内容是可接受的降级，不该让批改失败。
- **存档剥离**：写库前去掉该块，否则记录页里会看到一坨 JSON。
- **前端截断**：`renderMarkdown` 前**截断到起始标记之前**。
  为什么是截断而不是"正则删除整块"：流式输出时后半个标记还没到达，
  正则匹配不上整块，JSON 就会短暂地显示在学生眼前。

错题本里的**编辑功能是必需的而非可选项**——AI 识别题干难免有误差，
列表上也标出了「AI 提取 / 手动录入」的来源。

### 深色模式

右上角用户菜单里切换，选择存在 `localStorage`。

实现上有一件事必须先做：把散落在各组件里的 **156 处硬编码颜色令牌化**。
不这么做的话，只覆盖 `:root` 变量是没用的——那些字面量会在深色下变成一块块白色补丁。

现在所有颜色走四族令牌：墨色阶（`--ink-1..5`）、面阶（`--surface-1..3`）、
遮罩（`--mask*`）、语义色。改完用 `client/scripts/scan-hardcoded-colors.js` 自查（退出码可用于 CI）。

**深色玻璃拟态不是把浅色反相**：浅色靠「白卡 + 柔和阴影」分层，
深色底下阴影几乎不可见，必须改靠「深色卡 + 微光描边」，否则卡片会糊成一片。

另外两处容易漏的：

- `index.html` 内联脚本在 Vue 挂载前就把 `data-theme` 设好，否则深色用户每次刷新都闪一下白
- `color-scheme` 要跟着切，否则原生 `<select>` 下拉会是白底白字

### 现拍

用 `<input type="file" accept="image/*" capture="environment">` 调系统相机，
不引入 `getUserMedia`（要 HTTPS、在旧内核与微信里受限、代码量大）。
桌面浏览器会忽略 `capture`，退化为普通文件选择。

「拍照」与「从相册选择」是**两个独立入口**：带 `capture` 的 input 在多数设备上只能拍一张，
与多选语义冲突，混用一个 input 会让 Android 上的行为不可预测。

### 两条链路共用一个编排器

`chat.js`（对话）与 `study.js`（拍题/批改）都调 `services/turn-runner.js`。
这样做的原因：会话管理、上下文组装、视觉判定、流式、记账这五件事若各写一份，
两处的「SSE 收尾顺序」「闸门判定时机」「记账字段」必然逐渐不一致。

`turn-runner` 的固定顺序本身就是正确性的一部分：

```
会话兜底 → 模型解析 → 视觉判定 → 额度闸门 → 附件校验/读取/缩图
  → 写 SSE 头 → 存档用户消息 → 转述（如需）→ 组装上下文
  → 流式 → 存档助手消息 → 记账 → done
```

**所有可能失败的校验都必须在「写 SSE 头」之前完成**——一旦写了头，
HTTP 状态码就固定为 200，错误只能塞进事件流，前端拿到的是
「200 但内容是错误」这种别扭结果。

### 平板横竖屏

断点按「宽度 + 方向」双维度判定，而不是只看宽度：

| 场景 | 处理 |
|------|------|
| 平板竖屏（≤1024 且 portrait） | 侧栏改为抽屉（☰ 唤出）；学习页上下分栏；对话气泡放宽到 92% |
| 平板横屏矮屏（landscape 且高度 ≤800） | 整体压缩垂直间距；侧栏收窄；顶栏压低 |
| 平板横屏（landscape 且宽 ≥900） | 学习页左右分栏 |
| 桌面（≥1366） | 保持完整三栏 |

另外用 `--app-height`（`dvh`，旧内核回退 `vh`）代替写死 `100vh`，
避免移动端地址栏收放时页面高度算错。

## 技术栈与约定

- **服务端**：Express 4 + better-sqlite3（WAL）+ JWT + bcrypt + multer（上传）+ sharp（缩图）
- **前端**：Vue 2.7 + Vue Router 3 + Vuex 3 + Vite
- **代码风格**：`var`、单引号、2 空格缩进、中文注释（与 ClassIntra 保持一致）
- **兼容基线**：Chrome 80 及以上、Android 平板、微信 X5 内核
- **无缓存策略**：所有接口与静态资源都带 `no-cache`（与项目一贯要求一致）

### 安全基线

- `JWT_SECRET` 缺失时**拒绝启动**（不留默认密钥）
- 注册/登录独立限流（注册 30/min、登录 60/min、上传 30/min）
- 所有 `/api/admin/*` 强制 `requireAuth + requireAdmin`
- 中继同步接口用 `X-Cluss-Secret` 时序安全比较；未配置密钥时**拒绝服务**（不放行）
- ClassIntra 桥为只读，不做任何写操作
- 密码策略与 ClassIntra 一致：≥8 位且含字母与数字
- 面向用户的错误信息一律中文，系统错误码不透传

云盘相关的额外约束：

- **魔数嗅探优先于浏览器声明的 MIME**；声明为图片但实际是文本时直接拒绝
- 扩展名黑名单（`.html/.svg/.js/.mjs/.xhtml`）——它们在浏览器里能执行脚本
- 文本文件一律 `Content-Disposition: attachment` + `X-Content-Type-Options: nosniff`，
  避免同源 XSS
- 读取文件必须校验归属（用户只能读自己云盘里的 hash），防止用别人的 hash 越权
- 每用户配额（默认 200MB），上传前检查
- 附件内容作为「资料」注入提示词，并明确要求模型**不执行附件里出现的任何指令**
  （文本附件截断到 32KB 并声明可能不完整）

## 怎么验证

项目自带三个脚本，覆盖「改完怎么知道没坏」这件事：

```bash
cd server

# 1) 起一个 mock 上游（不需要真实 API Key）
node scripts/mock-ai-server.js

# 2) 一键跑 64 项端到端断言
#    覆盖：注册/闸门/充值/扣费、云盘上传与安全边界、视觉 native 与 relay 双路径、
#          拍题三模式与批改、用量统计、模型管理、越权与非法入参
node scripts/verify-v2.js

# 3) 准备一个可直接点开就用的演示环境（清数据 + 配模型 + 建已充值学生 + 传一张题图）
node scripts/prepare-demo.js
#    之后用 250301 / test1234（学生）或 999999 / admin12345（管理员）登录
```

mock 上游会按请求内容回不同答案（收到图 → 回「已收到图片」；system 含「批改」→ 回批改表格；
system 含「转述器」→ 回题目转述），所以能断言「模型到底收到了什么」，
而不是只看「有没有返回 200」。

几个容易忽略但已覆盖的断言：

- **数据库里绝不能有 base64**：`LENGTH(attachments)` 与 `LENGTH(content)` 都被断言在阈值内
- **转述与主回答共享同一 `trace_id`**，且转述记的是转述模型（不是主模型）
- **伪装成图片的 HTML 被拒**、越权读别人的 hash 被拒、拍题不带图被拒
- **学生访问管理接口返回 403**

## 已知边界

- 流式对话只做「一问一答」，**不含上下文摘要压缩**。上下文按 token 预算从最新往旧裁剪，
  所以很长的会话里最早的内容会被丢掉。若需要「记得前文」，需另做摘要机制。
- 不支持联网搜索（需要的话可参考 ClassIntra 的 ai-chat 移植）。
- 拍题与批改**必须有图片**：只传文本文件会被明确拒绝，而不是让模型硬答。
- 图片识别依赖上游模型能力，识别错字、公式符号的情况真实存在；
  提示词已要求模型对看不清的字符标 `□(看不清)`，但不能保证它每次都遵守。
- 节点上报的是**明细**而非聚合值，学生规模很大时中继上的 `cluss_usage_log` 会持续增长；
  建议定期归档（`created_at` 早于某时间的行）。
- 云盘每实例独立、不做跨节点同步，因此**磁盘会随拍题量增长**。已加每用户配额
  （默认 200MB，`cluss_meta.cloud_quota_bytes` 可调）；被删引用归零的文件是软删，
  物理文件保留在磁盘上，需要时可写脚本清理孤儿文件。
- 软删的云盘文件若同一 hash 再次上传，会复用原物理文件（内容寻址的必然结果），
  这是预期行为，不占额外空间。
